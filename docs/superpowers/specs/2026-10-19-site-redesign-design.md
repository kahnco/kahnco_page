# kahnco.me 홈·블로그 개편 디자인

- 작성일: 2026-10-19
- 브랜치: `feature/site-redesign`
- 시안 근거: 브레인스토밍 비주얼 컴패니언 `person-home.html`(홈·블로그 목록·글), `apple-toss-v2.html`(서비스 전면 타일), `tokens-v2.html`(토큰)

## 1. 목표와 범위

홈(kahnco.me)과 블로그(kahnco.me/blog)를 하나의 디자인 언어로 다시 만든다.
토스·애플 결: 중립 회색 + 파랑 하나, 크고 굵은 글자, 넉넉한 여백, 장식 없음.

| 대상 | 처리 |
|---|---|
| `/`, `/services`, `/portfolio`, `/privacy` | 새로 디자인 |
| 블로그 목록·분류·글·시리즈, 광고 자리, 코드·수식·Mermaid | 새로 디자인 |
| `/yourthoughts/privacy·terms`, `/atomic-demolition/privacy·terms` | 문서 틀만 통일 (문구 변경 없음) |
| `/yourthoughts`, `/atomic-demolition` 앱 랜딩 | **변경 없음** |
| 프리렌더(SEO), Firebase 호스팅 설정, 라우트 URL | **변경 없음** |

홈은 제품 진열장이 아니라 **이현준이라는 개발자의 이야기**를 한다. 제품은 그 이야기의 증거로 뒤에 나온다.

## 2. 지켜야 할 규칙 (사용자 지정)

- 얼굴 사진 쓰지 않는다.
- 지어낸 인용문·추천사 쓰지 않는다.
- 칸코테크는 1인 회사이며 카피에서 그렇게 밝힌다. "우리 팀" 같은 다인 어투 금지.
- 경력 사실: 2021-08 첫 취업 → "개발 경력 5년". 2024 말부터 의뢰·프리랜스, 2026 자사 서비스.
- 금지 모양: 점 달린 eyebrow 라벨, 둘째 줄만 액센트색인 슬로건, 슬로건 풀어 쓴 리드 문단, 채운+외곽선 버튼 한 쌍, 테두리+그림자 둥근 카드, 제목 위 액센트 머리 라벨, 알약 배지, 모든 요소 같은 반경, 내용과 무관한 01/02/03 번호.
- 그림자는 **제품 이미지(폰·브라우저 틀)에만**.
- 앱 랜딩 두 개는 건드리지 않는다.

## 3. 디자인 토큰

### 3.1 색

| 토큰 | 라이트 | 다크 | 쓰임 |
|---|---|---|---|
| `--bg` | `#FFFFFF` | `#0B1022` | 페이지 바탕 |
| `--tile` | `#F5F5F7` | `#121834` | 회색 타일·코드 아닌 면 |
| `--text` | `#1D1D1F` | `#F5F5F7` | 제목·본문 |
| `--text-2` | `#424245` | `#D2D2D7` | 보조 문장 |
| `--text-3` | `#6E6E73` | `#A1A1A6` | 날짜·메타·캡션 |
| `--line` | `#D2D2D7` | `#424245` | 구분선 |
| `--link` | `#0066CC` | `#2997FF` | 링크 |
| `--btn` / `--btn-text` | `#0071E3` / `#FFFFFF` | 동일 | 채운 버튼, **한 화면에 하나** |
| `--soon` | `#BF4800` | `#FF9F0A` | '개발 중·베타' 글자 |
| `--deep` | `#0F1428` | `#0F1428` | 고정 남색 타일 (테마 무관) |
| `--on-deep` / `--on-deep-2` / `--on-deep-link` | `#F5F5F7` / `#A1A1A6` / `#2997FF` | 동일 | 남색 타일 위 글자 |

- 모든 글자/배경 조합 WCAG AA(4.5:1) 이상. 최저는 라이트 `--text-3` on `--tile` 4.66.
- 고정 남색 타일 쓰임: 홈 '네 겹' 섹션, 문의 띠, 블로그 대표 시리즈.

### 3.2 글자

- 서체: **Pretendard Variable 하나**(라틴 포함). jsDelivr `pretendard@1.3.9` dynamic-subset CSS로 불러오고 `preconnect` 지정. 코드: 시스템 mono(`ui-monospace, SFMono-Regular, Menlo, monospace`).
- Geist(woff 파일, `@font-face`)는 두 앱에서 제거.
- 굵기는 700·600·500·400 네 단계만.
- 숫자 열은 `font-variant-numeric: tabular-nums`.

| 이름 | 크기/굵기/자간 (데스크톱) | 모바일 |
|---|---|---|
| hello (홈 첫 인사) | 96 / 700 / -0.05em | 48 |
| section (섹션 제목) | 52 / 700 / -0.045em | 34 |
| tile (제품명) | 56 / 700 / -0.035em | 36 |
| post-title (글 제목) | 44 / 700 / -0.04em | 30 |
| say (큰 문장) | 32 / 500 / -0.03em | 22 |
| item (목록 제목) | 20 / 600–700 / -0.02em | 18 |
| prose (본문) | 18 / 400 / 줄간 1.85 | 17 |
| ui | 15.5–17 / 400–600 | 동일 |
| meta | 13–14 / 400 | 동일 |

### 3.3 모양·간격·움직임

- 반경: 버튼 999, 브라우저 틀·코드 14, 메모·이전/다음 18, 제품 카드 24, 폰 52(실물 비율).
- 최대 폭 1024px, 좌우 여백 22px(모바일 16–20px). 글 본문 700px.
- 섹션 위아래 120–140px(모바일 80–90px). 타일 사이 12px.
- 움직임: 스크롤 진입 시 0.6s 페이드업 1회, 펼침 목록 높이 전환. `prefers-reduced-motion: reduce` 면 전부 끔.
- 400px 폭에서 가로 스크롤 없음.

### 3.4 테마 전환

- 기본은 OS 설정(`prefers-color-scheme`). 헤더 ◐ 버튼으로 라이트↔다크 고정.
- 저장: `localStorage["kahnco-theme"]` = `"light" | "dark"`, 없으면 시스템. 같은 도메인이라 홈·블로그 공유.
- 적용: `<html data-theme="...">`. 첫 페인트 전 깜빡임을 막기 위해 각 앱 `index.html` `<head>`에 인라인 스크립트로 먼저 적용. `localStorage` 접근은 try/catch.
- `<meta name="color-scheme" content="light dark">`, `theme-color` 라이트/다크 각각.

## 4. 구현 구조

```
shared/design/
  tokens.css   # :root 라이트, [data-theme=dark] + prefers-color-scheme 다크, --deep 등
  prose.css    # 블로그 본문·약관 공통 (.prose): 제목·문단·목록·표·인용·코드·KaTeX·Mermaid
  theme.ts     # getTheme / setTheme / toggle, ◐ 버튼에서 사용
  theme-inline.js  # head 인라인용 최소 스크립트 원본 (빌드 시 그대로 삽입)
```

- 루트 앱: `src/styles/site.css` 를 `tokens.css` 위에서 새로 쓴다(`.site` 스코프 유지). 앱 랜딩 전용 스타일은 손대지 않는다.
- 블로그 앱: `blog/tailwind.config.ts`(Tailwind 3.4) 의 색을 CSS 변수(`var(--bg)` 등)로 매핑. 하드코딩된 색(`bg-[#0a0a0a]`, `text-blue-400` 등)을 토큰 클래스로 교체. `blog/src/index.css` 에서 Geist 제거, `tokens.css`·`prose.css` import.
- 두 앱 모두 `shared/` 를 상대 경로로 import (Vite 기본 동작, 별도 패키지화 안 함). 필요 시 `server.fs.allow` 에 상위 폴더 추가.
- 공통 헤더/푸터 마크업은 앱마다 따로 두되 같은 토큰·같은 구조를 쓴다(React 컴포넌트 공유는 하지 않음 — 두 앱의 빌드가 독립이라 YAGNI).

## 5. 화면별 구성

### 5.1 공통 헤더·푸터

- 헤더 높이 48px, 반투명 `--bg` + blur. 왼쪽 'Kahnco', 오른쪽 '서비스 · 포트폴리오 · 블로그 · ◐'. 모바일은 메뉴 접힘.
- 푸터(애플식): 작은 회색 글자. 사이트 링크 묶음, 회사 정보(`COMPANY`: 칸코테크·대표 이현준·사업자번호·주소·이메일), 개인정보처리방침 링크, 저작권 한 줄.

### 5.2 홈 `/`

순서대로:

1. **첫 인사(전체 화면)**: "안녕하세요, 이현준입니다." + "앱부터 웹, 서버, 인프라까지 **혼자서 끝까지** 만드는 개발자입니다. 칸코테크는 제가 제 이름을 걸고 일하는 1인 회사입니다." 버튼·배지 없음.
2. **이야기**: 왼쪽 고정 제목 "회사에서 배우고, 맡아서 만들고, 이제 제 것을 만듭니다", 오른쪽 연도 세 개.
   - 2021 회사에서 전 과정을 배웠습니다
   - 2024 남의 서비스를 끝까지 만들어 드렸습니다
   - 2026 지금은 제 서비스를 만들고 운영합니다
3. **네 겹(남색 타일)**: "한 사람이 네 겹을 다 맡습니다" — 앱 / 웹 / 서버 / 인프라 계단식, 각 층에 쓰는 기술.
4. **숫자**: 개발 경력 5년 · 제작 이력 13건 · 지금 운영 중 3 · 기술 블로그 92편. 블로그 편수와 운영 중 개수는 데이터에서 계산(하드코딩 금지).
5. **이렇게 일합니다**: 펼침 목록 4개, 한 열, 최대 폭 720px. 내용은 숨고 프로필의 약속(계약서 기반 범위·일정, 진행 상황 수시 공유, 검수 후 하자보수, 기획부터 운영까지)을 근거로 쓴다. 인용문 없음.
6. **만든 것**: 제품 카드 5개 가로 레일(그래서요·사주쿠키·Atomic Demolition·베라페이블·더그아웃). 실제 화면 캡처 사용. `scroll-padding-left` 로 첫 카드가 본문 여백에 맞춤.
7. 링크 한 줄: "의뢰·재직으로 만든 13건 전체 보기 ›" → `/portfolio`.
8. **생각은 글로 남깁니다**: 최신 글 목록(`LATEST_POSTS`, 블로그 목록과 같은 선 구분 형식) + "블로그 전체 보기 ›".
9. **문의 띠(남색)**: "기획안 한 장이면 충분합니다" + 채운 버튼 하나(메일).
10. 푸터.

### 5.3 서비스 `/services`

- 서비스 하나가 **전체 화면 타일** 하나: `height: calc(100svh - 48px); min-height: 620px; max-height: 1100px`.
- 순서: 그래서요(sowhat.run) → 사주쿠키 → Atomic Demolition.
- 타일 구성: 이름(tile), 한 줄 설명(say), 실제 화면(폰/브라우저 틀, 그림자 허용), '사용해 보기 ›' 링크.
- 맨 아래 '곧 만나요' 2칸: 베라페이블 "비공개 베타 모집 중", 더그아웃 "개발 중" — 상태 글자는 `--soon`.
- 데이터: `src/data/services.ts` 에 그래서요·베라페이블·더그아웃 추가, `status: 'live' | 'beta' | 'building'` 필드 추가.

### 5.4 포트폴리오 `/portfolio`

- 묶음 세 개 유지: 자사 앱 / 의뢰·프리랜스 / 재직 프로젝트.
- 카드 없음. **연표형 목록**: 왼쪽 기간(tabular-nums), 오른쪽 이름·역할·기술 한 줄. 선으로만 구분.
- 데이터 수정(`src/data/portfolio.ts`):
  - 쿠펀 추가 — 의뢰(제이솔루션), 기간 표기 "의뢰 · 약 8개월 (실작업 약 2개월)"
  - 축신 기간 "2024.12 ~ 2026.04 · 인수인계 완료"
- 맨 아래 문의 띠(남색).

### 5.5 블로그 목록 `/blog`, 분류 `/blog/category/…`

- 맨 위: "기술 블로그" + "N편의 글"(데이터에서 계산). 소개 문단 없음.
- **대표 시리즈(남색 타일)**: 가장 최근 완결 시리즈 하나(현재 AI의 수학적 기초 7/7). 그 아래 나머지 시리즈를 '이름 · 편수' 글자 목록으로.
- **분류 탭**: '전체 · 실전·튜토리얼 26 · Flutter 21 …' 글자 탭. 선택된 탭만 굵게+밑줄. 알약 없음. 기존 `CategorySidebar` 를 이 탭으로 대체.
- **글 목록**: 위아래 가는 선 구분, 제목(item) → 요약 한 줄 → '시리즈 n편 · 날짜 · 읽는 시간'(meta). 썸네일 없음.
- 분류 페이지는 같은 틀, 제목만 분류명.
- 프리렌더된 정적 목록(크롤러용)은 그대로 유지.

### 5.6 블로그 글 `/blog/:slug`

- 본문 폭 700px, `prose.css` 적용. 제목(post-title) 아래 메타 한 줄.
- **시리즈 글**: 본문 위 접는 목차 "이 시리즈의 7편 중 3편 ▾" (기존 `SeriesNav` 개편).
- **코드 블록**: 반경 14, 라이트·다크 모두 짙은 배경, 시스템 mono. highlight.js 색은 토큰에 맞춘 자체 테마 하나.
- **KaTeX·Mermaid**: 글자색을 `--text` 로 따라가게. Mermaid 는 테마 전환 시 다시 그림(`theme: 'base'` + themeVariables 를 토큰에서 주입). 다크에서 흰 박스 없음.
- **쿠팡 배너**: 기존 위치(본문 중간=가전·디지털, 끝=완구·취미) 유지. 공정위 고지 문구를 배너 바로 아래 meta 크기 `--text-3` 로 **반드시** 노출. 위아래 여백으로 본문과 분리.
- **끝**: 이전 글 · 다음 글 2칸(반경 18) → '같은 분류의 글' 3편 목록.
- AdSense 로더·메타·ads.txt 는 그대로.

### 5.7 약관 (5쪽)

- 대상: `/privacy`, `/yourthoughts/privacy`, `/yourthoughts/terms`, `/atomic-demolition/privacy`, `/atomic-demolition/terms`.
- 공통 문서 틀 컴포넌트 하나(`LegalDocument`): 문서 이름, 시행일, 목차, `prose` 본문.
- 목차: 넓은 화면은 오른쪽 고정, 좁은 화면은 위에 접힘. 조항 제목에서 자동 생성.
- **문구는 한 글자도 바꾸지 않는다.** 기존 페이지의 본문을 틀로 옮기기만 한다.

## 6. 상태·예외

- 블로그 글 없음/분류에 글 없음: "아직 글이 없습니다" 한 줄 + 전체 목록 링크.
- 없는 글 slug: 기존 동작(404 처리) 유지, 같은 틀로 표시.
- 제품 이미지 로드 실패: 틀은 유지하고 `--tile` 배경만 보임(레이아웃 흔들림 없게 `width/height` 지정).
- JS 꺼짐(크롤러): 프리렌더 HTML 이 OS 테마 기준으로 읽을 수 있어야 함(`prefers-color-scheme` CSS 만으로 다크 동작).

## 7. 검증

- `npm run build:site` 성공, 프리렌더 HTML 에 본문·목록이 그대로 들어있는지 확인.
- 라이트/다크 × 데스크톱(1280)/모바일(390) 으로 홈·서비스·포트폴리오·블로그 목록·글(코드·수식·Mermaid 포함 글)·약관 캡처 확인.
- 400px 에서 가로 스크롤 없음, 테마 전환 후 새로고침해도 깜빡임 없음, 홈↔블로그 이동 시 테마 유지.
- 앱 랜딩 두 쪽이 개편 전과 동일한지 캡처 비교.
- 쿠팡 고지 문구 노출 확인.

## 8. 하지 않는 것

- 앱 랜딩 재디자인, URL 구조 변경, 블로그 글 내용 수정, CMS 도입, 공용 React 컴포넌트 패키지화.
